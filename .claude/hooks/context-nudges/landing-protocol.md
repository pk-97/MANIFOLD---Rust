# Landing reminder

The lead lands with `scripts/land_branch.py <branch> --worktree <path> --message '...' [--close-bead <id> ...]` (`.claude/GIT_TREE_DISCIPLINE.md` section 2): it merges `origin/main` into the branch, gates the merged tree with `scripts/landing_gate.py`, merges `--no-ff` to main, pushes, closes the beads, and re-gates when main moved. Branch rules (no cherry-picks, when a branch may be deleted) are in CLAUDE.md Hard rules. **The gate is for landing, not for finding reds**: one run reports every red with a `rerun:` command each; fix each red with that focused command (one test, one flow, one clippy package), then gate once more. Never loop the whole gate on one failure. The workspace sweep + `scripts/feature_matrix.py` are NOT landing items — nightly `scripts/trunk_health.py` runs them on main and files beads on red.

**Shipping = supersession sweep, same session.** Update the design doc status header and close the bead, then `rg` the design name and its stage labels across `docs/` and the memory directory; fix or tombstone every stale hit. Status lives in one place per fact. The sweep ends with the lifecycle call: keep the doc as a cited contract or `git rm` it (git keeps every version) — `design_status.py --lifecycle-check` (gate-enforced via `docs_lifecycle.rs`) flags any shipped doc nothing live cites and any status header over the word budget (state + owed items + one pointer; history goes to the body or beads — the hook docstring is the spec). No new files in `docs/landings/`: landing prose goes in the merge commit.
