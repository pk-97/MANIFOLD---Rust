**Seat rule (Peter, 2026-08-19): lead only.** Lanes never run PNG verification — it is evidence the lead acts on and a lane grinding a render loop burns its window. Lane briefs name the expected visual outcome; the lead renders and looks post-commit.

The "renderer is custom, can't screenshot here, must ask Peter to eyeball" assumption — stated repeatedly in `docs/UI_DESIGN_SYSTEM_AND_INSPECTOR_REDESIGN.md` — is **outdated**. Visual UI changes CAN be self-verified headlessly: `GpuDevice::new()` runs windowless, `UIRenderer` rasterizes a `UITree` (or immediate `draw_rect`/`draw_text` calls) to a `GpuTexture`, readback → `image::save_buffer` PNG, then `Read` the PNG.

**Primary tool = the `ui-snap` harness** (`crates/manifold-app/src/ui_snapshot/`, feature `ui-snapshot`, run `cargo run -p manifold-app --features ui-snapshot -- ui-snap <scene>` or the `cargo xtask ui-snap` alias). It drives the REAL `UIRoot`/`state_sync` path → PNG in `target/ui-snapshots/<scene>/`. Scenes (2026-07-01):
- `timeline` — whole timeline (inspector dropped). `--interact "select:<layer>"`, `--dump`, `--thumbs`, `--vs-mockup`.
- `states` — 6-state matrix in one image.
- `inspector` — selected layer + real Mirror→Bloom chain + an armed teal LFO drawer. The inspector was invisible before (other scenes zero its width). Built through real `sync_inspector_data`.
- `graph` — the **node-graph editor canvas only** (nodes/typed ports/wires) **+ real per-node output thumbnails for effects**. `--preset <TypeId>` picks any effect or generator (default Mirror; e.g. `--preset Tesseract`). Canvas synthesized from the catalog (`loaded_preset_view_by_id` → `snapshot_for_view` → `ui_translate::graph_snapshot_to_ui`); thumbnails from a **headless one-frame graph render** (`EffectGraphDef::into_graph` with a `PrimitiveRegistry::with_builtin` registry → `Executor::execute_frame_with_gpu` + `set_dump_all` → `dump_resources()`), blitted over each placeholder at `GraphCanvas::visible_node_thumbnails` rects. A UV-gradient fixture feeds the effect's `Source`, so spatial effects are legible. **No content thread needed.** **Generators are structure-only** (gated): a single raw-executor frame can't reproduce correct generator output — particle warmup / per-frame state / HDR tonemap live in the content pipeline, so geometry/particle generators render white/black. Follow-up: drive generators through `GeneratorRenderer` (state + warmup). See [[project_node_output_preview]] — same per-node-dump machinery the live editor's node atlas uses (`dump_textures`).
- `editor` — the **FULL graph-editor window**: left preview sidebar (chrome only, no live monitor images — those are content-thread-bound), center canvas (same machinery as `graph`), right card lane (the real `ParamCardPanel` + inner-node param list). `--preset <TypeId>` — **generator presets only** so far (the fixture builds a one-layer `Project` via `fixtures::generator_editor_fixture` so `editor_card_config` resolves a real card; effects need a chain, not built yet). Layout is preview-left/card-right (matches the main timeline's inspector docking right) — added 2026-07-01 by swapping the original card-left/preview-right layout per Peter's request, which required updating the live app's hit-testing/jump-to-node logic in lockstep (`app_render.rs`, `window_input.rs`), not just the headless render — see `feedback_eliminate_bug_class_at_storage_layer`-style "single source of truth" risk noted inline at `EDITOR_CARD_LANE_WIDTH`'s doc comment.
- `all` — renders timeline/states/inspector/graph/editor in one process.

Full doc: `docs/HEADLESS_UI_HARNESS.md`. Older seeds in `crates/manifold-renderer/tests/` (`headless_ui_spike.rs`, `ui_color_swatches.rs` with `SWATCH_OUT=<dir>`) still work for one-off contact sheets but the harness is the canonical path now.

**How to apply:** for any inspector/timeline/graph visual change, render the matching scene and Read the PNG instead of gating on Peter. He still signs off on *taste*; correctness (distinct steps, no overlap, drew at all, right structure) is self-checkable. `Color32 → LinearColor`/`TextColor` conversions are in `node.rs`; no gamma re-encode, so the PNG matches in-app rendering.
