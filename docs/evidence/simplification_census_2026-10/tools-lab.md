## How "live" was decided

Tracked Python under `tools/`: 389 files (eval 307, lab 37, manifold_audio 21, catalog 10, train 5, three top-level audio_analysis files, segmentation 4, two loose converters). I built a strict import graph (static `from`/`import` lines plus the places that import by computed name), then walked it from the roots `lab/*`, `catalog/*` and `kick_container.py`. That reaches 127 files, 79 of them in `eval/` (37 imported by the lab or catalog directly, 42 only through other eval files). A file outside that set has no importer in anything the lab can load. The lab's run id hashes the bytes of every module it loads (`lab/run.py` `module_hashes`), so the set is also exactly the set whose edits move run ids.

"cmds" counts in the proof are transcript commands that name the file in the last 30 days. They include `cat` and `rg`, so they overstate real runs.

## Traps for the deleting lane

- **Run ids and cache keys.** `lab/run.py` `module_hashes()` hashes the file bytes of every loaded module under `tools/`, and `lab/cache.py` `code_id()` hashes function source keyed by file path. Deleting 001 touches nothing either hashes. 002 edits files they do hash: every later run gets a new run id once, and any moved function in a `code_id` closure (`kick_fusion_features`, `kick_fusion_bandwise`, `kick_attack_rejection.causal_features`, `detector_cands`, `snare_cands`, the `kick_goal_*` measures) invalidates the content-addressed caches. The guide already says "never edit `kick_fusion_features.py` or `kick_fusion_bandwise.py`". 002 must leave those function bodies byte-identical.
- **Computed-name imports** (the regex graph misses these; each is listed in the proof): `eval.{family}_labels` (7 sites), `eval.kick_stable_{rms,quadrature}` in `kick_hybrid_experiment.py:54`, `eval.kick_{tonal,pcen}_experiment` in `run_kick_dsp_experiments.py:75`. The two `kick_stable_*` files and their tests are therefore live and are not in 001.
- **Rust cites Python as provenance.** Nine closure files are named in Rust comments as the port source (`kick_goal_templates.py`, `note_pitch.py`, `kick_goal_tail_features.py`, `kick_goal_lowbank.py`, `kick_goal_profile.py`, `kick_complex_onset.py`, `kick_fusion_bandwise.py`, `kick_fusion_features.py`, `live_kick_baseline.py`). They stay.
- **Scoreboard records** (`eval/scoreboard/*.json`, 49 tracked, 29 dated 2026-10-09) name the deleted scripts. They are the results; leave them.
- **One fixture reader goes with 001.** `tests/fixtures/audio_labels/evening_validation_passages_2026-10-09.json` is read only by `kick_night_extra_passages.py` (in the batch) and records `review_kick_evening_passages.py` as its source path.
