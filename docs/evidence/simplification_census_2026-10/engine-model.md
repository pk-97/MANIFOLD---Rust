## Method gap in the screen

`census_refs.py` counts two things as uses that are not: a `//` comment that names the item, and the `impl X {` and `impl Trait for X {` header lines of the type itself. So a struct or enum with an `impl` block can never read DEAD or TEST-ONLY, and a doc comment in another file keeps a dead function alive. A copy of the tool in the scratchpad that skips both (`census_refs_nocomment.py`, based on the census tool, same `pub_items.yml`) re-ran the four crates:

| crate | DEAD | TEST-ONLY | CRATE-ONLY | rows the screen did not list |
|---|---|---|---|---|
| foundation | 0 | 3 | 5 | 0 |
| core | 58 (+4) | 19 (+3) | 175 | 7 |
| editing | 12 | 37 (+32) | 36 | 32 |
| io | 2 | 5 (+1) | 28 | 1 |

38 of the 40 added rows are in the candidate table (the 32 editing structs are engine-030 to engine-041; the core and io ones are in engine-003, 009, 013, 023, 024 and 043); the other 2 (`has_audio_mods`, `is_layer_fed`) are in the kept list. The same blind spot applies to the other crates; the lead may want the fix (skip comment hits and a type's own impl headers) in `census_refs.py` before the other sweeps are reviewed. Hits inside a function's own body (recursion) and uses only by other dead items are still counted as uses, so cascades need the deleting lane's `cargo check`.

- CRATE-ONLY rows other than those the rerun moved. Narrowing visibility removes no lines (3.13).
- Items that are not `pub`, trait methods, anything under `#[cfg(test)]`, `testkit` and `test_support` modules.
- Uses only by other dead items beyond the cascades named in the rows (the deleting lane's `cargo check` finds the rest).
- Line counts for test removals are estimates (`~`): nothing was built or run.
- Whether each unwired command struct (engine-030 to engine-041) has an app-side successor beyond the ones named; the lane should name it.
- Names shared with a trait method, outside `service.rs` (see "Second blind spot").
- Macro-built names: none of the four crates uses `paste` or `concat_idents`; the 5 `macro_rules!` in them do not build item names from candidates. `extern "C"` and `no_mangle`: none in the four crates. `build.rs`: only core's, which sets an environment variable.
- `raw/project_versions.txt`, migrations and legacy shapes (fallbacks sweep).
- `tools/`, `scripts/`, docs fixes (tooling sweep).
