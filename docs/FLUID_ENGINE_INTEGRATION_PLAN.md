## 2. Decisions

**D1 — Shared interaction API, specialised backends.** Put field evaluation, impulse semantics and tick identity in `manifold-physics`; FLIP consumes them. Retain concrete `PhysicsWorld` and `FluidWorld` ownership. Rejected: a fluid-only force system, because it duplicates exactly the scene interaction boundary Peter wants shared. Also rejected: replacing both solvers with a universal engine framework before users can try fluid.

**D2 — Scene authoring over a parallel editor.** Add Fluid and Force to the Scene Panel, using ordinary graph nodes, stable node references, parameter surfaces and undoable edits. Existing objects can acquire Source, Drain and Collider roles. A Scene modifier may compose a behaviour using these inputs; it is not required to create fluid. Rejected: a hardcoded demo selector or a separate fluid timeline.

**D3 — Compose shape, strength, targets and timing.** Uniform, radial and vortex fields are useful starting blocks. Sum, scale, spatial masks and user-supplied sampled vector fields provide composition. An explosion is a radial field with a triggered impulse/envelope preset. It has no privileged engine action or fixed relationship to an audio band.

**D4 — One authored input stream, fixed simulation time.** Keep the current 60 Hz outer tick initially, independent of display/export FPS; native substeps remain internal. Beat-addressed automation, events and recorded external inputs feed that clock. Rejected: increasing force per displayed frame or rerunning stateful trigger nodes during historical sampling.

**D5 — Same solver across quality levels.** Draft and final use FLIP with the same authored controls and recorded inputs. Different spatial resolution can change motion and event outcomes; promise consistent intent and timing, not identical trajectories. Rejected: silently switching solvers or resolution during a take.

**D6 — Two-way interaction is in scope.** Shared fields affect liquid and rigid bodies. P8 makes static/animated/Box3D-driven colliders displace liquid with coherent timing; P8b returns liquid pressure and viscous reaction to dynamic bodies, including angular response. Reuse native FLIP pressure/viscosity and Box3D mass/inertia through `manifold-physics`. Rejected: independent buoyancy/drag heuristics presented as physical coupling, or claiming two-way support merely because the solvers exchange poses. This is substantial integration; the P8b feasibility gate determines whether a larger solver project is necessary.

**D7 — Reuse collision assets, keep visible detail independent.** Photoscans use the existing proxy/cooking path. A detailed render mesh need not be its collision mesh. Preserve concavity when the source representation permits it; never silently replace a bowl with its solid convex hull.

**D8 — Separate simulation, meshing and appearance.** Viscosity/surface tension alter simulation; surface reconstruction alters mesh output; absorption/refraction/roughness alter rendering. Water and honey presets set these deliberately but leave them editable. Runtime-mutability is capability metadata, not a promise that every native setting can change safely mid-step.

**D9 — Scene and resource foundations (2026-09-28).** The next delivery covers
ordinary object ownership and controls, coherent object lifecycle, fluid resource
growth, exposed quality settings and shallow-water retention. Bake/cache workflow
design is the next discussion, not part of this delivery. Legacy FLIP obstacle
objects migrate to the existing grouped object and Collider role representation;
their authored transform and stable parameter bindings survive. Loose objects
share an exclusive-upstream ownership walk for deletion and duplication, retaining
shared inputs. Object-owned fluid role controls belong to their source object.
Enable Physics explains unsupported configurations; remove an explicit Fluid Role
before converting its source to a rigid body, which participates in scene coupling
automatically.

Mesh allocation grows without resetting the simulation or truncating geometry,
including downstream array consumers and recorded snapshots. `max_capacity`
remains a compatible initial allocation hint, not an output ceiling. Growth uses
the GPU's buffer/working-set admission and reports allocation errors. The former
96-resolution and native 128³-total checks are removed. Resolution has an 8–512
default authoring range; the exposed Grid Budget defaults to eight million native
cells and can be increased deliberately. Native indexing and actual memory remain
constraints. Whitewater retains its separately exposed particle budget. Resolution,
transfer, whitewater and surface controls use ordinary parameters; changing solver
setup restarts its epoch. CPU cost grows with grid and meshing detail; these controls
do not imply real-time operation.

**Surface tuning development, 2026-09-29 (BUG-3sta).** Peter requested a separate
simulation → surface → render workflow on `codex/fluid-surfacing`, with no main
landing until visual approval. `FluidWorld::capture_surface_frame` is the first
in-memory boundary: an explicit copy of completed particle positions and prepared

The application still uses its existing mesh cache and restart behaviour; no new

for the requested frame/settings. No solver steps during remeshing, no automatic
resolution changes, no computer use, and no GPU-compute rewrite are permitted in

short motion renders, and do not repeat passed checks without new evidence.

The captured-frame API now has an experimental isolated-particle scale
(0.25–1, default 1). Particles with overlapping reconstruction spheres keep
their main radius; the scale blends in as nearest-neighbour distance increases
from two to three main radii. This preserves connected water and keeps the
control relative to cell size, independently of mesh detail. It does not resize
detached multi-particle clusters, guarantee identical fluid behaviour across
resolutions, or preserve droplets smaller than the selected meshing grid.
Classification is retained while tuning the same snapshot. The control remains
outside application UI/live playback until bounded visual qualification.

`FluidWorld::set_surface_reconstruction_enabled(false)` opts a newly created
world out of per-step mesh construction before its first step. Physics and

empty mesh that could be mistaken for missing liquid. This is an opt-in native
API for future bake jobs; the application still reconstructs each native frame.

The authored domain describes usable liquid space. Native grids add three cells
per axis for FLIP's 1.5-cell boundary margins, keeping cell spacing and authored
bounds consistent. Initial liquid, role geometry, rigid coupling, force sampling,

## 3. Architecture and ownership

```text
Scene graph + ordinary parameters + existing event/modulation sources
                         |
       content-owned preparation and timestamped input capture
                         |
        manifold-physics shared fields, impulses and tick contract
                   /                            \
       PhysicsWorld / Box3D             FluidWorld / CPU FLIP
                   \                            /
           accepted poses, fluid mesh and whitewater
                         |
               existing scene renderer / manifold-gpu
```

Dependency direction: `manifold-physics -> manifold-foundation`; add `manifold-fluids -> manifold-physics`. Neither crate depends on the renderer, UI or project model. `manifold-physics` must not depend on `manifold-fluids`. It defines the common language, not knowledge of every backend.

The content thread owns authored state and prepares immutable input snapshots. UI sends existing `ContentCommand`/`EditingService` edits and receives snapshots. Native worlds have exclusive owners. Reuse the fluid worker's bounded request/reply channels, cancellation epochs and recycled buffers. No new shared mutable locks or independent event bus.

For a connected rigid/fluid scene, one worker owns both native worlds and advances their shared tick. Independent rigid-only scenes retain their existing path. The shared scheduling module lives in `manifold-physics`; renderer graph preparation maps scene references to its runtime handles and supplies backend operations. Extract the common scheduling policy rather than retain two divergent debt/event implementations. Native process-global locks remain private to their existing crates.

Physical membership follows the existing `render_scene` object membership and provenance. A scene containing one liquid domain and one rigid world couples its visible body slots and copies using the installed Box3D collision proxies; material children deduplicate to their original body. Render-only, rigid-only and fluid-only scenes remain independent. Repeated views of the same pair merge recipient masks. Preparation rejects multiple domains/worlds in one coupled scene, or one participant assigned to different partners across scenes, until a multi-domain owner exists. Nested groups keep their existing `NodeId`/`SceneNodeRef` identities. `instantiate_def` resolves `prepare_coupled_scenes` bindings through its local node map, including effect splices, and configures ownership before evaluation. `RigidSceneObservation` exposes the same resolved body, copy, field and playback inputs consumed by the ordinary world node; pending, invalid or withheld historical inputs must clear it. The compiler closes liveness over each pair and contracts its two nodes into one topological group after both input ancestries. It expands that group as adjacent liquid evaluation then rigid publication, before either consumer. Direct or indirect cyclic participant dependencies fail preparation. The executor captures rigid inputs without advancing a private world, lets the existing liquid worker advance both, then latches the accepted rigid frame. Historical samples use the existing retained CPU parameters and same group order. No extra scene/GPU evaluation is introduced.

The shared substep protocol is now `manifold-physics::stepping::{StepCoupling, SubstepExchange}`. `RigidSimulation::advance_with_coupling` retains the existing authored histories, fixed tick, contacts and once-only event queue; the rigid-only path supplies `Uncoupled`. Each tick borrows a participant frame, queues motion/forces before each stability offer, applies the participant reaction, steps Box3D once and finishes the participant before accepting the tick. `finish(&PhysicsWorld)` captures the final native rigid state before deferred authored teleports or releases can change it. `manifold-fluids::RigidFluidCoupling` binds existing collider/body handles and retains state/impulse scratch; it translates poses and centres of mass into the axis-aligned domain, uploads fresh dynamics before CFL selection and applies one validated reaction batch. Its `completed_bodies` view pairs scene-space rigid state with the finished fluid frame; beginning another frame invalidates the view before reusing scratch. Failed exchange or capture invalidates the native fluid frame and must retain the previous published pair. Scene preparation must rebuild both worlds and this adapter together when topology or epoch changes, and latch a completed pair before evaluating either participant's graph outputs. The existing fluid worker now accepts resolved `RigidSceneInputs`, owns both native worlds, exports installed Box3D hulls into FLIP and drains the same rigid owner one requested tick at a time. `FluidRuntime` maps transport once and publishes `CoupledRigidFrame` only with the matching liquid epoch/tick; copied body inputs retain the existing `InputHistory` semantics and native interpolation. The bounded worker policy bypasses presentation budgets, retains remaining debt, and rejects topology replacement inside an epoch. Connected graph membership and publication now use this shared request. Impulse preparation maps rigid recipients to the liquid owner and unions selected material/body targets, so one source event targeting both participants is admitted once. The paired clock uses Physics World speed; either independent reset counter resets the pair once, including simultaneous changes. Liquid density is authored in kg/m³ and changes rebuild the pair. World gravity inheritance and UI ownership of shared speed/gravity remain required followups; currently liquid scalar gravity and rigid XYZ gravity retain separate authored values.

The P8 collision baseline applies queued edits/events, samples continuous controls, applies rigid forces, steps Box3D, provides previous/current rigid poses as the FLIP collision interval, steps FLIP and publishes both results with one tick stamp. Animated collider poses come from the authored interval. If FLIP needs a next pose, extrapolate from the accepted end velocity and label this approximation; do not advance Box3D an extra visible tick. This intermediate checkpoint has no fluid reaction and is not the completed coupling implementation.

P8b extends that same owner and clock with per-body pressure/viscous reaction impulses and moments about each body's centre of mass. The native adapter must derive them from the boundary treatment used by FLIP, preserving obstacle identity, density/units, substep duration and epoch. Fixed/animated bodies remain externally constrained; only dynamic bodies receive feedback. Do not add buoyancy on top of pressure reaction or a second generic drag force on top of viscous reaction. Both native worlds must reach an accepted coupling boundary before publication; failed steps invalidate that interval instead of exposing a half-updated pair.

At each coupled substep, queue the existing shared forces, read Box3D's pose/dynamics and native pending external accelerations, then obtain FLIP's CFL offer. FLIP predicts boundary velocity as current velocity plus accepted substep duration times external acceleration, solves pressure/viscosity and returns only the fluid impulse. Apply that impulse and advance Box3D once for the accepted duration; its ordinary step consumes the queued forces. Prediction does not include damping, gyroscopic torque or contacts, so moving contact and viscous cases still require acceptance. Resample/reapply continuous forces for each substep because Box3D clears its force queue after a step. Do not duplicate the existing field evaluator or integrate gravity twice.

The initial partitioned candidate was rejected by P8b's bounded native pressure fixture: a light body gains energy even with the exchange interval halved. The native PCG extension now includes rigid mass/inertia in that pressure solve and its preconditioner, passing the bounded pressure-stage gates below without feedback damping or altered masses. It remains part of this workstream; no replacement solver has been introduced. Geometry attribution, viscosity and moving-body acceptance must pass before freezing the public coupling API. P9 records the accepted method/version/settings in cache identity.

This costs throughput: a coupled scene presents at its slowest required solver's accepted time. Publishing a new rigid pose over stale water would break contact alignment. Preview retains the previous coherent result and reports lag; offline waits. Other uncoupled scenes must not be enlisted in that wait.

### 3.1 First committed shared API

Add `crates/manifold-physics/src/interaction.rs`, re-exported by `lib.rs`. These are runtime types, not a second project serialization format. Arrays follow the existing native-wrapper convention.

```rust
pub trait VectorField: Send + Sync {
    /// Dimensionless world-space vector at a world-space position.
    fn sample(&self, position: [f32; 3]) -> [f32; 3];
}

pub struct FieldInput<'a> {
    pub field: &'a dyn VectorField,
    pub acceleration: f32,   // metres / second²
    pub delta_velocity: f32, // metres / second, consumed once this tick
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct TickStamp {
    pub epoch: u64,
    pub tick: u64,
}

impl PhysicsWorld {
    pub fn apply_fields(
        &mut self,
        bodies: &[BodyHandle],
        fields: &[FieldInput<'_>],
        dt: Seconds,
    ) -> Result<(), PhysicsError>;
}
```

`apply_fields` samples each dynamic body's centre of mass; the adapter converts acceleration to force using body mass and velocity change to a mass-scaled impulse. Fixed/animated bodies retain their authored behaviour. Spatial torque, explicit force-at-point in newtons and impulses in newton-seconds remain Box3D-specific capabilities; do not pretend the centre-sampled field produces torque.

`VectorField` is the extension seam, not a list of prescribed actions. Implement immutable prepared uniform/radial/vortex fields, arithmetic composition and trilinearly sampled grids. Masks and transforms are part of the prepared evaluator; validate finite outputs and non-singular transforms before a tick. No allocation inside `sample`. Target selection resolves to recipient lists during preparation, not string searches per cell/body.

Add to `manifold-fluids/src/lib.rs` in P6:

```rust
impl FluidWorld {
    pub fn step_with_fields(
        &mut self,
        dt: Seconds,
        fields: &[manifold_physics::FieldInput<'_>],
    ) -> Result<FrameStats, FluidError>;
}
```

Keep `step(dt)` as the compatibility entry with no additional fields. The bridge uses the existing native `ForceField` extension to supply a prepared field, using reusable grid storage; it must not retain the borrowed Rust inputs after the call. Combine acceleration with `delta_velocity / dt` for that outer interval so the impulse integrates once across adaptive native substeps. Verify this against the native integrator before exposing the control: pressure projection and collisions can change the resulting liquid velocity, but impulse strength must not multiply with substep count. Failure of that conformance test blocks this adapter, not permission to patch arbitrary particle velocities.

Common semantics are world metres, seconds and vectors. Default World gravity is `[0, -9.81, 0]`; newly added fluids share it through ordinary graph wires. Add Fluid reuses or creates one root World. Unwired gravity XYZ, speed and reset bindings retain their existing outer IDs, conversion and modulation while moving to ordinary `node.value` sources shared by World and liquid. Already-wired World controls retain their authored upstream signal. Exposure migration does not add sliders for newly wired fallback inputs; existing explicit bindings remain intact. The primitive rejects differing coupled speeds rather than ignoring an authored input. Explicit per-domain gravity override UI remains unfinished and must use existing graph/mux composition. Renderer history and native FLIP retain all three gravity components. The serialized liquid `gravity` parameter remains Y for compatibility; optional `gravity_x` and `gravity_z` default to zero. Shared controls appear under World; physical density remains in the Fluid inspector. Existing scale-dependent viscosity/tension coefficients retain their honest artistic labels.

### 3.2 Geometry and solver capabilities

Coupled body proxies come from `PhysicsWorld::hull_meshes`: setup-time copies of the actual installed Box3D hull surfaces, in body-local coordinates and native shape order. Re-cooking source points is not an equivalent export: the standalone cooker caps at 42 vertices, while an installed hull can retain more. Three focused tests cover a 48-vertex prism, separate compound parts, pose/dynamics preservation, ownership after world drop and foreign/terrain rejection; the real owner exchange fixture now consumes this export. Static triangle-mesh terrain remains on its existing geometry path. `FluidWorld::prepare_rigid_coupling_groups` binds a nonempty group of colliders to each body's pose, mobility and reaction. The shared owner accepts repeated body handles and exchanges each body once, in first-occurrence order. Separate hulls retain their union geometry; do not merge overlapping triangles into a parity surface or apply body mobility independently to each hull. Native capture capacity still accounts for raw collider contributions before body aggregation; large-scene storage qualification remains open.

Replace singleton native source/obstacle ownership with per-world handle tables. Stable graph references map to opaque, provenance-checked runtime handles, following `BodyHandle`; handles are never project IDs. Support Initial Fill, Inflow, Outflow and Collider independently, including multiple instances and transformed meshes. Initial Fill runs at epoch creation/reset; inflow/outflow remain controllable during playback.

Use one prepared collision asset for all consumers where suitable: cooked hull sets can become FLIP boundary triangles; static triangle proxies preserve concavity. Geometry buffers and revisions are immutable; poses update without recooking. Resolve scaling at preparation, accept translation/rotation per tick, and reject invalid/non-manifold volume input with an actionable object name. Collider thin-shell handling must follow verified upstream capability rather than guessing that every open scan encloses liquid.

**P3 verified dependency and bridge contract:** collision work is merged. Renderer `physics_mesh::prepare_colliders` supplies `ColliderGeometry { hulls }`; `manifold_physics::cook_hull_mesh` now exposes the same native cooked hull as `TriangleMesh { vertices, triangles }`, with winding, closed-edge and volume tests. Reuse those proxies; do not introduce another decomposition pipeline. Static closed triangle surfaces may preserve concavity.

The native role bridge accepts the shared `TriangleMesh` and `BodyPose` (translation plus xyzw quaternion). Scale is baked during preparation; poses are in domain-local metres. `FluidWorld::add_mesh(mesh, role, pose)` returns an opaque world/slot/generation `MeshHandle`. Roles are `Inflow`, `Outflow`, and `Collider`; initial fill uses `add_fluid_mesh(mesh, pose, velocity)` without a retained handle. `set_mesh_motion(handle, previous, current, next)`, `set_mesh_enabled`, and `remove_mesh` operate on registered roles. `set_inflow_options` controls velocity and motion inheritance; `set_collider_friction` controls the verified native friction coefficient. Reject role mismatches and foreign/stale handles before mutation. `set_boundary_collisions([bool; 6])` uses upstream order −X, +X, −Y, +Y, −Z, +Z.

Validate finite, nondegenerate, consistently wound closed volume topology at preparation. Report rejected open/non-manifold meshes instead of replacing them with boxes; names are attached by scene preparation. ## 5. Timing, events and lifecycle

Continuous inputs and discrete events share a capture clock but remain distinct. Capture events at their existing producer boundary with beat/time and a stable sequence number; resolve authored beats using the project tempo rules. At preparation, map references to runtime recipients. Capture resolved strength, transform and targets for an impulse so later edits cannot rewrite an already queued hit.

The fixed interval is `[t_n, t_(n+1))`. Events in that interval apply once at tick n; an event exactly on the upper boundary belongs to the next tick. Order equal-time events by producer sequence; reset ends the old epoch before applying following events to the new one. Never use a display-frame pulse as the queue. Late input enters the next unstarted tick with lateness recorded; it does not mutate an already published tick. Offline playback uses the recorded applied tick to reproduce a live take, including this quantisation.

A coupled liquid/rigid group admits each source event once through the existing fluid worker queue. Its resolved target can select liquid, rigid body/copy slots, or both under one captured field and source stamp. The rigid owner consumes the already assigned tick without admitting the event a second time: source sequence order can differ from delivery-time order. One common receipt preserves the original source, assigned tick and lateness; it records an attempted tick, including native failure, rather than claiming successful completion. Standalone liquid callers retain their field-only receipt adapter, which leaves mixed receipts available to the group recorder.

Retain continuous input history until its consuming tick completes. Sample stateless authored curves at physics time. For live audio/external data, retain actual timestamped feature/control samples and use hold/interpolation rules appropriate to each value. Do not synthesise historical audio by reusing today's frame context. Offline source audio passes through the existing analyzer at audio/control cadence and produces the same timestamped stream independently of output FPS.

| Action | Behaviour |
|---|---|
| Pause / resume | Hold the accepted state; discard paused wall time. Resume at the next simulation tick. |
| Normal clip edge | Preserve the scene's simulation. A reset occurs only when the user binds it. |
| Explicit Reset | Cancel old work by epoch, restore initial fill, clear old events; keep authored bindings. |
| Seek / backward loop in Live | Start a new epoch and reset; display the reset state honestly. No false reconstruction of uncomputed history. |
| Seek with a valid bake | Address the cached timeline. No native simulation and no newly applied live force. |
| Need an exact live-state seek | Replay from bake start/pre-roll using recorded inputs; indicate preparing until the requested time is reached. Geometry caches are not checkpoints. |
| Topology/setup edit | Prepare resources off the content hot path, cancel old epoch and restart once. Undo restores authoring, then follows the same rebuild rule. |
| Hidden/removed scene | Stop scheduling hidden simulation; reactivation resumes without hidden elapsed time. Removal cancels and releases owned resources. |
| Lag / capacity / native error | Retain coherent output, expose the affected scene and measured lag/error. Do not silently drop impulses, lower resolution or claim current-time output. |

The shared input queue is bounded and reuses storage. Overflow pauses the affected simulation with a visible diagnostic and retains the recording prefix; it cannot silently overwrite unread history. The UI offers Restart or Bake, rather than asking for CFL/substep tuning.

The discrete queue lives beside `InputHistory` in `manifold-physics::input` and reuses `TickStamp`. `EventStamp { epoch, time: Seconds, sequence }` identifies one captured input; `EventQueue<T>` owns its resolved payload. Construction fixes epoch, origin, tick duration and capacity. `enqueue(stamp, value)` returns the planned tick; `begin_tick(tick, consume)` advances the next-unstarted cursor and delivers `AppliedEvent<T> { source, applied, lateness: Seconds, value }` in time/sequence order. Delivery records assignment to a started tick, not successful native completion. Native step/publish failures remain the world's responsibility. Only the next consecutive tick may start, including empty ticks. Input sequence increases on arrival; timestamps may arrive out of order. A later source observation cannot rewrite a started tick. `reset(new_epoch, new_origin)` requires a newer epoch, cancels unread old events and reports their count. Invalid calls leave state intact; capacity exhaustion latches until reset. The owner keeps this runtime-only queue on its existing simulation/content path; there is no new thread, serialized graph state or recipient registry.

This separates event retention from `InputHistory`'s interpolation: an impulse cannot be represented by replacing a continuous endpoint or by a cumulative frame counter, because either loses its resolved payload and application time. Tick boundaries use actual floating-point interval endpoints without a tolerance that pulls adjacent representable times across a boundary. The queue does not create a live audio clock or infer one from render delivery; producers still need the source mapping described below.

The renderer runtimes accept already resolved scene-space delta-velocity fields through `RigidSimulation::enqueue_impulse` and `FluidRuntime::enqueue_impulse`. Callers use the initialized runtime's `impulse_epoch`; source time must already be mapped into that simulation epoch. Rigid inputs capture a body-slot mask and the reset-latched copy group. A topology/reset/seek rebuild cancels old inputs, and absent recipients or stale epochs are rejected. The graph-facing `EffectNode` hooks forward admission and receipts to these same owners; they do not add queues or infer events from counters. Manual generator Fire now feeds this seam; audio/clip producer mapping and effect-hosted events remain unfinished.

`PresetRuntime::prepare_scene_impulse` reuses the force recipient resolver and prepares a stateless CPU field ancestry. Capture owns the resolved field and target selection in preallocated storage. Several visible parts sharing one body are deduplicated, and body slots/copies sharing a world are merged into one queue entry. Event-only field branches can register their outputs as runtime graph roots; validation, compilation, executor liveness and resource retention all honour those readers. Changed output roots invalidate prepared capture plans until the host rebuilds them. Scene recipes now declare event-only field outputs by scoped node/port and local trigger parameter. Expansion retains those outputs before compilation; host parameter aliases resolve from the canonical owner without introducing numeric counter nodes.

`capture_scene_impulse_at_source` closes the previously held input interval, observes current live CPU controls at the source timestamp and obtains each native world's accepted simulation clock. Speed changes and pauses use the existing authored history; capture never drains native ticks, even when called inside an offline render scope. It rejects older source observations, unavailable native inputs and withheld setup changes. The host must finish scene setup/GPU geometry evaluation before capturing, and apply resolved controls in timestamp order. This API cannot reconstruct old audio controls from current parameters; `capture_scene_impulse` remains available to callers with an explicit recorded clock mapping. Reset/rebuild identity and native epochs prevent a retained hit from reaching a replacement world. `deliver_scene_impulse` records each successful admission before proceeding: a partial failure remains visible and retry cannot duplicate the admitted prefix. This is not atomic cross-world delivery; coherent scene scheduling remains P8. Native tick-start receipts retain the source stamp, payload and lateness for the future take recorder. Source-capture CPU tests cover matching applied ticks and native rigid motion at 24/30/60 FPS and a display stall, speed edits, pause, setup/reset rejection and fluid worker non-advancement. They do not establish end-to-end audio or UI delivery.

Worker handoff is an explicit input boundary. Sending a FLIP request seals all its tick inputs; a later arrival is assigned after that request, with lateness measured against the original source timestamp. Admission returns a planned tick. The worker reply separately identifies ticks that actually began, including a subsequently failed tick, and only those become delivery receipts. Neither admission nor receipt asserts successful native completion. The existing preview request may contain its whole backlog, so this batching can add latency; coherent shared-scene scheduling remains P8 work. Runtime admission is bounded to 256 outstanding impulses across queued inputs, worker-owned batches and undrained receipts. Storage is reused; overflow or native tick failure halts delivery until reset instead of replaying or overwriting inputs. Legacy FLIP Record/Playback modes reject impulses until P9 records their identity.
